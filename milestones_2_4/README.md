# Folk-painting restoration: dataset + pipeline (Kaggle-first)

## 1. Where everything goes on Kaggle
```
/kaggle/input/folk-restore-code/        <- you upload folk-restore.zip as a Kaggle Dataset (read-only, code only)
/kaggle/input/<some-kaggle-dataset>/    <- optional extra datasets you attach with "Add Input" (read-only)

/kaggle/working/folk-restore/           <- THE working folder = your notebook's Output. Every command runs from here.
    *.py, README.md, requirements.txt   (copied from /kaggle/input/folk-restore-code by notebook cell 1)
    data/
      raw/<style>/*.jpg                 dataset (written by 00_collect_dataset.py / 00b_ingest_folder.py)
      real_damaged/*.jpg                5-10 damaged paintings moved here by 00c_contact_sheet.py --copy
      sources.csv                       where every image came from + its licence
      tiles/, synthetic/, manifest.csv  generated by steps 01-02
    runs/unet_rich/best.pt              trained segmenter (step 03)
    results/, figures/, sheets/         numbers and slide images
```
`/kaggle/working` is writable and is what Kaggle calls *Output*. `/kaggle/input` is read-only. All scripts use relative paths, so the only rule is: **run them with `/kaggle/working/folk-restore` as the current directory** (the notebook does this for you).

**Do this once:**
1. kaggle.com -> *Datasets -> New Dataset* -> drag in `folk-restore.zip` -> name it `folk-restore-code` -> Create.
2. *Code -> New Notebook* -> *File -> Import Notebook* -> upload `folk_restore_kaggle.ipynb`.
3. In the notebook: *Add Input* -> select `folk-restore-code`. Settings: **Accelerator = GPU, Internet = On** (Internet is needed for dataset download and for pretrained weights).
4. Run the cells top to bottom. They do everything below.

Same thing on Colab or locally: copy the folder anywhere, `cd` into it, run the same commands.

## 4. What each stage is (so the slides stay honest)
- **Segmentation:** U-Net, ResNet-34 (ImageNet-pretrained), 5-channel input (RGB + CLAHE-L + black-hat), 3 outputs (crack, loss, stain); trained only on synthetic damage generated on the fly (`degrade.py`).
- **Inpainting:** pretrained Big-LaMa, **zero-shot, not fine-tuned**, vs OpenCV Telea; scored with ground-truth ("oracle") masks and with our predicted masks. Scored on the un-faded damaged tile so fading doesn't pollute it.
- **De-fading:** (a) baseline: global Reinhard transfer toward the training-set palette; it increases colour error because every painting has its own palette. (b) model: a U-Net that predicts a LAB colour correction, trained on simulated fades (15% of samples are un-faded so it learns to leave healthy colours alone). On real images it is applied at strength 0.7 by default (`--defade_strength`); the real fading is unknown, so judge those results by eye.
- **Uncertainty (v1, step 5):** `*_unc.png` is segmentation entropy only. Superseded by the four-signal confidence map of `restore.py` (section 6).
- Real images are processed at long side <= 1536 px (`--max_side`), one whole-image LaMa pass.
- Numbers on the synthetic test set measure handling of *simulated* damage; real-image results are qualitative. Say so.

## 5. Troubleshooting
- Collector prints `FAILED` or 0 images for a source: the others continue. Re-run later, or collect the same way on your laptop (`pip install requests opencv-python`, same commands) and upload `data/raw` as a Kaggle Dataset, then use `00b_ingest_folder.py`.
- Wikimedia/museum 429 errors: the script waits and retries; raise `--sleep 1.0`.
- A real image shows > ~40% "damaged area": raise `--thr 0.7` in step 6 and inspect `*_mask.png`.
- LaMa out of memory: `--max_side 1024`. Training out of memory: `--bs 8`.
- Don't press *Save Version* with thousands of tile files; download `deliverables.zip` and `raw_dataset.zip` (last notebook cell) instead.
- Tested: every script end to end on a fake dataset on CPU, the collector against mocked API responses, the real LaMa weights. **Not tested:** the live museum/Commons endpoints (the sandbox I wrote this in can't reach them), a GPU run, ImageNet encoder weights, Real-ESRGAN.

Design notes (so the report stays honest):
- **Inpainting** is *fine-tuned* pretrained Big-LaMa, not trained from scratch. TorchScript keeps gradients, so this works without the LaMa training repo. If fine-tuning does not beat zero-shot on validation, `best.pt` is the pretrained model and the script says so.
- **De-fading** conditions on the mean/std (LAB) of an un-faded strip. In training the "margin" is a strip of the clean tile; on real paintings it is whatever region you pass with `--margin`. Real fading is not the simulator's fading, so judge real results by eye.
- **Super-resolution** is Real-ESRGAN x4plus (official weights, own RRDBNet implementation), run in overlapping tiles with a linear blend. `--sr 2` is x4 then area-resampled. SR on bicubic-downsampled tiles may score LOWER PSNR than bicubic and still look sharper (LPIPS shows that); both are reported.
- **Confidence map** = four signals (segmenter entropy, depth inside the hole, disagreement between 3 inpainting runs, discriminator realness), fused with fixed weights (`uncertainty.WEIGHTS`, a judgement call, not tuned). Step 12 reports how well each signal predicts real error; the fusion weights should follow those numbers.
- **Not tested here:** the sandbox had no GPU and no access to your dataset, so every script was smoke-tested end to end on CPU with a fake dataset (random shapes), tiny models and 1-2 epochs. Real-ESRGAN weights, Big-LaMa weights and the tiled-SR code were run for real; VGG/LPIPS weights could not be downloaded there. No metric from the fake runs is meaningful.

## 7. v3: wall-mural damage (for photographs of painted walls)
`degrade.py` now has `profile` = `paper` | `wall` | `mixed`, `scale_jitter` and `photo`:
* **wall**: chalky plaster flaking (fill colour from a plaster/ochre/brick palette, grain, shadow rim), salt blooms, rain streaks (all labelled loss/stain).
* **scale_jitter**: damage is rendered at a random 0.5-2x scale, so crack width and hole size vary relative to the painting.
* **photo**: blur, sensor noise, JPEG blocking, uneven illumination and colour cast on the segmenter input.

```
python 02_make_synthetic.py --profile wall --scale_jitter 0.5 --photo 0.5 --out_name synthetic_wall --seed 321
python 03_train_unet.py --name unet_v3 --decoy_prob 0.4 --profile mixed --scale_jitter 0.5 --photo 0.5 --val_dir data/synthetic_wall/val
python 04_evaluate.py --ckpt runs/unet_v3/best.pt --test_dir data/synthetic_wall/test --out results_v3_wall --no_lama
python 13_diagnose_real.py data/real_damaged --ckpt runs/unet_v3/best.pt --out results/diagnose
```
Caveat: wall damage is still a simulation. It can only be judged on real images by eye (or by hand-labelling a few).
